# KANJAM - Every Rupee Counts

A rebuilt, offline-first Flutter version of the KANJAM expense tracker. Same identity as the
original app (black + #00E676 green, wallet logo, Home / Credit / Debit / Budget / Goals /
Reports / Notifications / Profile / Settings), with every feature wired to real stored data.

> **Status - read this first.** The source was written without access to the Flutter SDK
> (the build sandbox could not reach pub.dev or Google's SDK hosts). It has been checked with
> the structural tools in `tools/dev/`, but it has **not** been through `flutter analyze`,
> `flutter test` or `flutter build apk`. Run the commands below on your machine; if anything
> is reported, send it back and it gets fixed. No APK is included for that reason.

## Build and run

```bash
# 1. Generate the Android host project with your own Flutter version + KANJAM branding
bash tools/setup_android.sh                       # Windows: powershell -ExecutionPolicy Bypass -File tools\setup_android.ps1

# 2. Dependencies, auto-fix style lints, analyse, test
flutter pub get
dart fix --apply
flutter analyze
flutter test

# 3. Run / build
flutter run
flutter build apk --release                       # -> build/app/outputs/flutter-apk/app-release.apk
```

Why `setup_android` instead of shipping `android/`: Gradle/AGP/Kotlin versions must match the
Flutter version installed on your machine, so the host project is generated by `flutter create`
(same application id as the old APK, `com.kanjam.finance`) and only the branding is applied.
Release builds are signed with the debug key until you add your own keystore.

## How it works

| Area | Design |
| --- | --- |
| Storage | Hive boxes holding plain maps (`toMap` / `tryFromMap`), so there are no generated adapters and no `build_runner`. Boxes are opened once, before the UI. A corrupt box is reset and the user is told. Unreadable single records are skipped. Box names are `kanjam_v2_*`. |
| State | `provider` + `ChangeNotifier` services (one per entity). `FinanceCoordinator` owns cross-entity rules (a transaction also raises budget alerts, onboarding creates accounts...). |
| Balances | Never stored. `balance = opening balance + credits - debits`, derived by `FinanceCalculator`, so add / edit / delete can never leave totals out of step. |
| Navigation | `AuthGate` picks the screen from saved state (sign-in, next unfinished onboarding step, PIN lock, app), so login, logout and restart cannot leave stale routes. |
| Auth | Local only. Salted, iterated SHA-256 for passwords and the PIN. Password reset uses the recovery email/phone given at sign-up (there is no server to email). |
| Notifications | In-app notification centre (budget 80% / 100%, goal updates, new transactions), controlled by the In-App Notifications switch. |

```
lib/
  core/       constants, theme (dark + light palettes), formatters, validators, money, crypto
  models/     user, account, transaction, budget, goal, notification_item
  services/   storage, auth, accounts, transactions, budgets, goals, notifications,
              settings, finance_calculator (pure maths), finance_coordinator
  widgets/    cards, charts (custom painters), logo, wave, inputs, dialogs
  screens/    splash, auth, onboarding, home, transactions, credit, debit, budget,
              goals, reports, notifications, profile, settings, lock
test/         calculator, validators, models, formatters + crypto
tools/        setup_android.sh|.ps1, dev/ (offline source checkers)
```

## Tests

`flutter test` runs unit tests for the calculation engine (balances, month filtering, weekly
buckets, budget levels, float drift), validators, model round-trips with corrupt records,
formatters and hashing.

## Offline source checkers (optional)

`tools/dev/syntax_check.py` (brackets / structure, needs `pip install tree-sitter tree-sitter-dart`)
and `tools/dev/xref_check.py` (imports, constructor arguments, member names) were used because no
Dart SDK was available. They do not type-check. `flutter analyze` is the source of truth.
